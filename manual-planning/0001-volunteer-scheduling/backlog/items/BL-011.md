## Summary

Two halves of one restructuring, merged because they rewrite the same six files and each invalidates the other's diff:

1. **Auth** — six Fastify controllers repeat the same session-resolution and volunteer-context bootstrap in controller-local `preValidation` hooks. Centralize the shared core behind a policy-parameterized factory, keeping authorization policy explicit and readable at each call site.
2. **Route ownership** (ex-[BL-013](./BL-013.md)) — `admin-leader-controller.ts` mixes Event, TimeSlot, Assignment and Ministry routes under one controller, one `/admin` prefix and one flat `'admin'` OpenAPI tag. *"Admin"* describes **who may call a route**, not **what it is about**. Split by domain, retag by domain, re-home the paths.

## Full Context

### The six hooks are near-identical

All six run the same three-step preamble — resolve session (401), `resolveVolunteerContext` (401), decorate the request — and differ in exactly one role predicate:

| Controller | Predicate | Sets `request.userId` |
| :-- | :-- | :-- |
| `church-admin-controller.ts:118` | `!ctx.isAdmin` | yes |
| `leader-controller.ts:98` | `!ctx.isLeader && !ctx.isAdmin` | yes |
| `leader-rostering-controller.ts:113` | `!ctx.isLeader && !ctx.isAdmin` | yes |
| `admin-leader-controller.ts:93` | `!isAdmin && !isLeader && !isScheduleBuilderRoute` | yes |
| `volunteer-controller.ts:69` | *(none)* | **no** |
| `volunteer-schedule-controller.ts:27` | *(none)* | **no** |

**Four distinct policies across six controllers.** The original hedge in this item — *"not byte-for-byte identical, so the right extraction is probably not a single opaque hook"* — is too cautious: it factors cleanly into a **policy-parameterized hook factory**. Note that the two volunteer controllers omit `request.userId`; a shared factory erases that inconsistency, which is additive and harmless but must be **called out in the diff rather than discovered**.

### Route metadata and tagging, confirmed

67 routes. `summary:` appears once, `description:` three times, all in `church-admin-controller.ts`. `tags: ['admin']` covers **53 of 67** routes across four controllers — `admin-leader` (14), `church-admin` (19), `leader` (11), `leader-rostering` (9). Only `feature-flag-controller.ts` (`['feature-flags']`) and the two volunteer controllers (`['volunteer']`) are clean.

`admin-leader-controller.ts` registers 14 routes spanning Event (`/events`, `/events/:eventId/cancel`, `/events/:eventId/reminders`), TimeSlot (`/events/:eventId/slots…`), Assignment (`/assignments…`), a `/ministries` listing, and the legacy `/schedule-builder` GET.

### ⚠️ Retagging without the orval allowlist deletes routes silently

`orval.config.ts` generates the web client with `output.mode: 'tags'`, `clean: true`, and `input.filters.tags: ['admin','volunteer','feature-flags']`. **Retagging routes by domain without updating that allowlist silently removes them from the generated client, with no error.**

The mitigating fact: the generated modules are consumed through a single façade, `apps/web/src/utils/api-instances.ts:1-3` — three import lines — so call sites using `adminApi.listEvents(...)` never see the split.

### ⚠️ The `/admin/schedule-builder` carve-out is load-bearing, and untested

`apps/web/src/routes/scheduling.tsx:6-12` guards `/scheduling/*` on **authentication only** — no role check. Any authenticated volunteer can reach `/scheduling/tailoring/$ministryId/$cycleId`, and the server carve-out at `admin-leader-controller.ts:114` is what stops it returning 403. BL-013 called this route "legacy"; **it is not dead.**

The predicate is a URL string match: `request.url.startsWith('/api/v1/admin/schedule-builder')`. The server has exactly one test file (`volunteer-controller.test.ts`) — **no controller auth tests at all**. The only e2e reference (`apps/web/tests/scheduling/us2-leader-tailor.spec.ts:67`) authenticates as a leader, so it passes the normal role check and never exercises the exception. **The original success criterion 3 asserted coverage that does not exist.**

Because the path is moving, `request.url.startsWith(...)` would silently stop matching and 403 the tailoring page. The carve-out therefore survives as a **per-route policy declaration** ("any authenticated volunteer") against the controller's default of admin-or-leader — attached to the route, not to a string, and immune to path changes.

### Path re-homing cost, accepted explicitly

97 hardcoded `/api/v1/admin/...` strings live outside the generated client, all in Playwright specs (`us2-leader-tailor`, `us3-volunteer-availability`, `cross-cutting`, `planning-cross-tenant-isolation`, …). The generated web client regenerates for free; the fixtures do not.

The recommendation on the table was to **keep** `/admin` — Scalar groups by tag, not by path, so the ~97 edits buy no docs benefit on a suite already known to be flaky on this branch. **The decision went the other way**: paths are re-homed, with that cost accepted and explicit.

## Approach — full pass, in five ordered stages

Recorded as input to the `/to-prd` pass, not as binding sub-items.

1. **Five auth-policy tests first**, pinning the four distinct policies that exist today plus the carve-out, covering their 401/403 paths. Deliberately not a full per-controller test build-out — five tests pin what a behaviour-preserving refactor needs without turning this into a test-coverage project.
2. **Auth hook factory** with per-route policy override; all six controllers migrated onto it. Prefer a focused module near `apps/server/src/api/auth/` (e.g. `create-auth-prevalidation.ts`), not a generic "shared" folder — and only under `apps/server/src/main/fastify/` if it becomes a true app-wide plugin.
3. **Split `admin-leader-controller.ts`** into domain controllers (event / time-slot / assignment).
4. **Retag all four `['admin']` controllers by domain**, plus the `orval.config.ts` allowlist update and the `api-instances.ts` façade re-wire — composing `getEvents()` / `getTimeSlots()` / `getAssignments()` back into the same flat `adminApi` surface — **all in one commit**, so the client is never generated against a stale allowlist.
5. **Re-home URL prefixes off `/admin`**, plus the ~97 Playwright fixture updates.

## Prerequisites / Dependencies

None blocking. Coordinate with [BL-012](./BL-012.md) (blocked by this item) and [BL-017](./BL-017.md), whose guard this policy layer should absorb once both have landed.

## Success Criteria

1. Shared auth-context resolution lives in one place, and role requirements remain readable at controller call sites.
2. The `/admin/schedule-builder` exception survives as a **per-route policy**, not a URL string match, and is **covered by the five new tests** — closing the coverage gap the original criterion wrongly assumed existed.
3. `401`/`403` behaviour and request decoration are unchanged, with the `request.userId` normalisation on the two volunteer controllers called out explicitly in the diff.
4. No controller mixes routes from more than one clear domain purely because they share a caller-role requirement.
5. OpenAPI tags group routes by domain (Events, TimeSlots, Assignments, Ministries, …), with caller-role expressed separately if at all.
6. URL prefixes reflect the resource being operated on, not who may call it.
7. `orval.config.ts`'s tag allowlist and the `api-instances.ts` façade land in the same commit as the retag, and **no web call site changes**.
