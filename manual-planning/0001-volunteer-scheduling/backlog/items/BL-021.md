# BL-021 — Auth Route Protection & Sign Up Suppression (Invite-Only Flow)

**Status**: Backlog  
**Feature area**: Authentication & Routing (`apps/web`)

## Summary

The application operates on an administrative invitation model. Public self-registration (Sign Up) must be hidden from the UI, and all application features (dashboard, availability, scheduling, notifications, volunteer pages) must be protected behind authentication, redirecting unauthenticated users to Sign In.

## Full Context

Currently in `apps/web`:
1. The Sign In page (`/login`) renders a toggle between `SignInForm` and `SignUpForm`, defaulting to `SignUpForm`. Since account creation is administrative/invite-only, Sign Up must be hidden from public navigation.
2. `__root.tsx` mounts `<AppShell>` (sidebar, header) directly around `<Outlet />`. Unauthenticated users visiting any URL can see the application shell and layout.
3. Unauthenticated requests to root `/` or internal feature pages must be redirected to `/login`, and `/login` must render as a standalone public page without the sidebar/header chrome.

## Suggested Approach

1. **Sign Up Suppression:**
   - Make `onSwitchToSignUp` optional in `SignInForm` (`apps/web/src/components/sign-in-form.tsx`) and hide the Sign Up button when omitted.
   - Update `apps/web/src/routes/login.tsx` to render `<SignInForm />` directly and redirect authenticated users back to `/`.

2. **Route Protection & Layout Separation:**
   - Simplify `__root.tsx` to render `<Outlet />` inside `ThemeProvider` without `<AppShell>`.
   - Introduce a pathless protected layout route (`src/routes/_authenticated.tsx`) with a `beforeLoad` auth check (`authClient.getSession()`).
   - Move private routes (`/`, `/dashboard`, `/availability`, `/notifications`, `/scheduling`, `/volunteer/*`) under `_authenticated`, wrapping them with `AppShell`.

## Prerequisites / Dependencies

- `Better Auth` session client in `apps/web/src/lib/auth-client.ts`.
- TanStack Router file-based route tree in `apps/web`.

## Success Criteria

1. Public Sign Up toggle/links are removed from `/login`.
2. Unauthenticated visits to `/` or any internal route redirect to `/login`.
3. The `/login` page renders standalone without sidebar/header chrome.
4. Authenticated users can access all private routes with the full `AppShell` intact.
5. All route guard logic passes unit tests and Playwright E2E verification.
