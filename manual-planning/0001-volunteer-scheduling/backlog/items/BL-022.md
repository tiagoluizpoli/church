## Summary

The Planning Cycles table fires a whole-row `onAction` while rendering as a selectable row. Switch it to react-aria's native `selectionMode="single"` so selection is real, keyboard-operable and announced, instead of a click handler that behaves like a button.

## Full Context

### What the code actually does

- `features/scheduling/components/planning-admin/cycle-list-card.tsx:114-124` — `TableRow` carries `onAction`. **It drives `selectedCycleId` and a `bg-accent/45` highlight in a master–detail pane.** The row click **selects; it does not navigate.**
- `CYCLE_TABLE_COLUMNS` is name / window / status. There is **no** actions column, and no per-row actions exist today.
- Whole-row `onAction` is **a single call site** across all of `features/scheduling` — `calendar-row.tsx`, `cycle-review-card.tsx` and `template-manager-card.tsx` never use it.
- `ui/table.tsx` is **react-aria-components**, not shadcn (`Table`, `TableHeader columns={…}`, `TableBody items={…}`, `sortDescriptor`, `ResizableTableContainer`), so `selectionMode` is a primitive-level feature already available.

### ⚠️ What the original framing got wrong

The original text proposed replacing row clicks with *"explicit Action Buttons / Dropdown Menus matching Rostering conventions."* Two corrections:

1. **Click-to-select stays — it is correct here.** The ambiguity is not that the row is clickable; it is that `onAction` fires like a button while the row looks like a selection. Inventing `Open` / `Review` buttons for a table with no per-row actions would be parity theatre.
2. **Rostering's convention is not dropdown menus.** `CycleRowActions` (`ministry-cycle-list.tsx:270-311`) renders a flat `flex flex-wrap gap-2` row of `variant="outline"` buttons, size switched by `useFormControlSize()` between `sm` and `touch`, with `disabled` + `title` + `aria-label` on gated actions. "Dropdown menus" is struck from this item and does not enter `DataTable`'s API.

The **header / toolbar / empty-state parity clause has left this item** entirely — it is now [BL-024](./BL-024.md), rehoused where the `WorkspaceHeader` primitive will live so `cycle-list-card.tsx` is not edited twice for the same reason.

### Test-hook divergence

Tailoring rows carry `data-testid={\`ministry-cycle-row-${cycle.id}\`}`; cycle rows carry none. Success criterion 3 is therefore free on the Cycles side — there are no selectors to preserve — but **adding** them is part of reaching parity.

## Suggested Approach

1. Switch the Cycles table to react-aria's `selectionMode="single"`, giving real `aria-selected`, keyboard selection, and a selected style the primitive owns.
2. Remove the hand-rolled `bg-accent/45` highlight that `selectionMode` replaces, keeping `selectedCycleId` driven by the primitive's selection change.
3. Add per-row `data-testid` hooks matching the tailoring convention.
