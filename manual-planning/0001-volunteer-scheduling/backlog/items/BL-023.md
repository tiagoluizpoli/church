# BL-023 — Centralized UI Component Abstractions (`DataTable`, `WorkspaceHeader`, & Shared Primitives)

**Status**: Backlog  
**Feature area**: Frontend Architecture & Component Library (`apps/web`)

## Summary

Create central, composable UI component abstractions for shared elements across the application—specifically a generic `DataTable` component and standardized `WorkspaceHeader` primitives—so styling, behavioral rules, desktop/mobile responsiveness, and visual identity are maintained in one centralized space.

## Full Context

The application uses tabular layouts, header panels, and responsive desktop/mobile patterns across multiple features (Cycles, Tailoring/Rostering, Dashboard, Volunteer pages). Currently, many of these are re-implemented ad-hoc per page.

Creating centralized abstractions allows single-implementation updates to styling, keyboard accessibility, loading states, and responsive desktop-to-mobile layout transformations across the entire application.

## Suggested Approach

1. **Generic `DataTable<T>` (`src/components/ui/data-table.tsx`):**
   - Wrap existing `components/ui/table.tsx` primitives.
   - Accept generic `data: T[]`, typed `columns: ColumnDef<T>[]`, custom `actions` button/menu slot renderer, optional `onRowClick`, `isLoading` skeleton, and `emptyState` renderer.
   - Built-in responsive transformation: desktop `<Table>` on `md+` viewports; stacked `<MobileListCard>` layout on mobile viewports.
2. **Centralized Header & Intro Panel (`src/components/workspace-page.tsx`):**
   - Extract and standardize header primitives (`WorkspaceIntroPanel`, `WorkspaceHeader`, stat pills, action toolbars) so page headers across all domains compose from a single centralized API.
3. **Migrate Consuming Features:**
   - Consume `DataTable` and `WorkspaceHeader` across Cycles, Rostering, and other app pages.

## Prerequisites / Dependencies

- `apps/web/src/components/ui/table.tsx` primitives
- `apps/web/src/components/workspace-page.tsx`

## Success Criteria

1. Generic `DataTable<T>` primitive supports generic row types, column definitions, action slots, and mobile card fallback.
2. `WorkspaceHeader` / `WorkspaceIntroPanel` primitive centralizes header layout, statistics badges, and mobile actions.
3. Single implementation change in `DataTable` or `WorkspaceHeader` automatically propagates across all consuming pages.
4. Component unit tests verify composition, loading states, and mobile card rendering.
