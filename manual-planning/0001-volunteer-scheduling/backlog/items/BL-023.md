## Summary

Extract a `DataTable<T>` convention wrapper over the **existing** react-aria table primitive, owning only what the six current consumers genuinely duplicate: the responsive desktop/mobile pair, an actions render prop, loading skeleton, empty state, and selection-mode passthrough.

## Full Context

Six components consume the raw `ui/table` primitives ad hoc: `calendar-row.tsx`, `cycle-list-card.tsx`, `cycle-review-card.tsx`, `template-manager-card.tsx`, `ministry-cycle-list.tsx`, `ministry-tailoring-list.tsx`. No `components/ui/data-table.tsx` exists.

### ⚠️ Premise corrections

1. **`ui/table.tsx` is react-aria-components, not shadcn** (`apps/web/src/components/ui/table.tsx:1-33` — `react-aria-components/Table`, `TableHeader columns={…}`, `TableBody items={…}`, `sortDescriptor`, `ResizableTableContainer`; 552 lines). **It is already column-generic.**
2. **`@tanstack/react-table` is not a dependency** (`apps/web/package.json` carries react-form / react-query / react-router / react-virtual only). The original `ColumnDef<T>` wording implies it. **No new dependency is being added**, and column definition stays react-aria's existing `columns` / `items` render-prop shape.
3. **The duplication is a copied pattern, not divergent implementations.** Five of six sites already use the identical `space-y-3 md:hidden` + `hidden md:block` pair (`ministry-tailoring-list:95,121`, `ministry-cycle-list:165,199`, `template-manager-card:64,107`, `cycle-list-card:64,99`, `cycle-review-card:423,452`). That makes the extraction mechanical and lowers this item's risk considerably.
4. **The actions convention is inline outline buttons, not dropdown menus.** `CycleRowActions` (`ministry-cycle-list.tsx:270-311`) renders a flat `flex flex-wrap gap-2` row of `variant="outline"` buttons, size switched by `useFormControlSize()` between `sm` and `touch`, with `disabled` + `title` + `aria-label` for the availability-gated `Assign`. **`DataTable` does not impose a menu.**

### Why `WorkspaceHeader` left this item

`DataTable` and `WorkspaceHeader` share no code and no consumer list — six table call sites versus ten `WorkspacePage` / `WorkspaceIntroPanel` consumers. They are two items. The header work is now **[BL-024](./BL-024.md)**, ranked separately with no dependency between them.

## Suggested Approach

**`DataTable<T>` (`src/components/ui/data-table.tsx`)** wraps the existing react-aria `Table` and owns only what is genuinely duplicated:

- the `md:hidden` / `hidden md:block` responsive pair, with the **mobile card list as a slot**;
- an **`actions` render prop taking the row**, codifying `CycleRowActions` as the convention — a flex row of outline buttons, size from `useFormControlSize()` (`sm` / `touch`), `disabled` + `title` + `aria-label` for gated actions, one `data-testid` per action;
- loading skeleton and empty state;
- **selection mode passthrough**, per the contract [BL-022](./BL-022.md) settles.

Columns and rows keep react-aria's `columns` / `items` shape. Then migrate the six consumers onto it.

## Prerequisites / Dependencies

- `apps/web/src/components/ui/table.tsx` (react-aria-components)
- **[BL-022](./BL-022.md)** — landed 2026-09-10; the selection contract this wrapper encodes is settled.

## Success Criteria

1. `DataTable<T>` wraps the existing react-aria table without introducing a new table dependency, and preserves its `columns` / `items` API.
2. The responsive desktop/mobile pair, loading skeleton, empty state and actions convention live in exactly one place.
3. All six current consumers are migrated, and a single change in `DataTable` propagates to all of them.
4. Component unit tests verify composition, loading state, empty state, mobile card rendering and single-selection passthrough.
