**Status**: Parked
**Feature area**: Backend Architecture

## Summary

`leader-controller.ts` and `leader-rostering-controller.ts` both implement private `denyParticipationScope({ request, reply, participationId })` and `denyShiftScope({ request, reply, shiftId })` methods with the same shape: call `AuthorityGuard.canManageParticipation`/`canManageShift`, and on denial send a `403 FORBIDDEN` with an identical message, returning a boolean. Extract into one shared helper (e.g. a small module near `apps/server/src/api/auth/`) that both controllers depend on, rather than each carrying its own copy.

## Full Context

Found during the [#72](https://github.com/tiagoluizpoli/church/issues/72) review (`feat/049-retire-system-roles`, commit `1996d1b`) while migrating these controllers off the old `SchedulingRbacGuard` onto `AuthorityGuard`. The migration touched both copies in lockstep (same rename, same `FastifyReply`-thenable bug fix applied to both), which is itself a live demonstration of the duplication's cost — every future change to this guard shape has to be applied twice and kept in sync by hand.

Related but distinct from [BL-011](./BL-011.md): BL-011 is about the controller-level `preValidation` session/role-bootstrap hook (four different coarse role predicates across six controllers). This item is about the finer-grained, per-resource scope guards that sit *inside* route handlers, introduced by the AuthorityService migration — a layer that didn't exist when BL-011 was written.

## Suggested Approach

A shared helper function or small class taking `{ request, reply, authorityGuard }` plus the resource id and the `AuthorityGuard` method to call, returning the same `Promise<boolean>` contract used today (`true` = denied, reply already sent). Keep the 403 message text unchanged — call sites and existing tests assert exact message strings (see `leader-rostering.http.test.ts`'s "Shift belongs to another ministry" assertions).

## Prerequisites / Dependencies

None blocking. Natural to fold into [BL-011](./BL-011.md) if that item's auth-hook-factory stage ends up touching these same two files.

## Success Criteria

1. `denyParticipationScope` and `denyShiftScope` exist in exactly one place, imported by both controllers.
2. No change to the 403 status codes, error codes, or message strings for any existing route.
3. Existing `leader.http.test.ts` and `leader-rostering.http.test.ts` assertions pass unmodified.
