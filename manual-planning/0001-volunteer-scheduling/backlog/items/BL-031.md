## Summary

Use a Wayfinder map to turn the repository's 2026-09-21 [Twelve-Factor App](https://12factor.net/) audit into a deliberately scoped operating model. The map decides what to adopt, defer, and explicitly decline; it must not treat all twelve factors as a technology checklist.

The primary target is the web/API service. The desktop client and Fumadocs site need separate applicability decisions rather than inheriting server requirements.

## Wayfinder Questions

Create one `wayfinder:map` issue and use child research/decision/task tickets only where the answer changes implementation. Resolve these questions in order:

1. **Operating envelope** — single instance or replicas; uptime/recovery expectations; selected host/platform; the release and rollback owner.
2. **Applicability** — which factors bind the API, web PWA, desktop client, and Fumadocs independently.
3. **State and concurrency** — whether public rate limiting needs a shared store, whether the outbox remains in-process or becomes a worker, and what failure/retry guarantees are required.
4. **Release contract** — one immutable build artifact; config injection; migration timing and rollback boundaries; dependency/runtime version policy.
5. **Lifecycle and observability** — shutdown deadline, readiness/liveness semantics, structured log shape, and the log sink/retention owner.
6. **Parity** — which local, CI, staging, and production services must match and which differences are intentional.

Every decision must end as exactly one of **adopt**, **defer with trigger**, or **decline**, with the operating-envelope evidence that supports it. Create implementation tickets only for adopted decisions.

## Guardrails

- Preserve the factors already met unless a deliberate architecture decision replaces them.
- Avoid cargo-cult additions: Kubernetes, Redis, a queue, a separate worker, a container image, staging, or a log platform require a concrete operating need.
- Keep configuration values and credentials out of source control; improve the configuration contract rather than copying production values into examples.
- Treat the 12-factor site as a design lens, not a compliance certification.

## Success Criteria

1. A Wayfinder map links this item and records the operating envelope before any remediation ticket is ranked.
2. Each audit finding is classified as adopt, defer with a falsifiable trigger, or decline with rationale.
3. The map states the factor scope for API, web, desktop, and Fumadocs separately.
4. Every resulting implementation ticket has one bounded outcome and no ticket exists solely to improve a factor score.
